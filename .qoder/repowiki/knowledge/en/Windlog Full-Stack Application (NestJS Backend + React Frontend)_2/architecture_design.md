The repository is split into two co-located halves under the same root:

- Backend (`API/src`): NestJS application bootstrapped in `main.ts`, which registers global middleware (Helmet, CORS, compression), a global `ValidationPipe`, `HttpExceptionFilter`, `TransformInterceptor`, and `LoggingInterceptor`. The root `AppModule` imports feature modules (`AuthModule`, `UsersModule`, `ProjectsModule`, `UploadModule`, `NotificationsModule`, `WeeklyTimesheetModule`, `FeedbackModule`, `SystemLogModule`). Each module follows the strict `{name}.module.ts` + `{name}.controller.ts` + `{name}.service.ts` layout with DTOs under `dto/`. Prisma is the single ORM layer via `database/prisma.service.ts`; business logic lives only in services — controllers are thin HTTP adapters. Authentication uses `@nestjs/passport` with a custom `JwtStrategy`; roles (`ADMIN`, `HR`, `STANDARD`) are enforced via guards and route-level checks.

- Frontend (`src`): React SPA built with Vite, routing via `react-router-dom` defined in `App.tsx` with role-gated wrappers (`ProtectedRoute`, `AdminRoute`, `AdminOrHRRoute`). Data fetching uses TanStack Query (`QueryClientProvider` at the root). All API calls go through a centralized `services/api.ts` fetch wrapper that injects the JWT from `localStorage` and auto-logout on 401. Domain-specific services (`auth.service.ts`, `project.service.ts`, etc.) wrap endpoints; pages live under `pages/<feature>/` with colocated `components/` and `hooks/`. UI primitives are in `components/ui/`, layout components in `components/layout/`. Internationalization is driven by locale JSON files under `i18n/locales/pt/`.

- Database schema is the single source of truth in `API/prisma/schema.prisma` (PostgreSQL, UUID IDs, soft-delete via `deletedAt`, enums for all domain values). Types generated by Prisma flow into both backend services and frontend type definitions.
