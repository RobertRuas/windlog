The module is organized as a flat set of single-responsibility service files under `src/services/`. Each service file exposes pure async functions (no class instances) that call the centralized `api` client from `api.ts`, which wraps the browser `fetch` API with JWT handling, 401 auto-logout, and JSON serialization. Every service defines local `ApiResponse<T>` interfaces matching the NestJS TransformInterceptor envelope (`data`, `message`, `statusCode`, `timestamp`). Business entities are modeled as TypeScript interfaces co-located in the same file as their CRUD functions. There is no DI container or class-based architecture — services are stateless modules imported directly by pages/hooks. Dependency direction is strictly one-way: services → `api.ts` → `localStorage` for tokens; no service imports another service.
