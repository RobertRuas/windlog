Standard NestJS feature module following the project's prescribed layout: `feedback.module.ts` registers `FeedbackController`, `FeedbackService`, and `PrismaService`; `feedback.controller.ts` exposes REST endpoints under `/api/v1/feedbacks` with JWT authentication via `AuthGuard('jwt')` and admin-only routes guarded by `RolesGuard` + `@Roles(Role.ADMIN)`; `feedback.service.ts` contains all business logic — CRUD operations, soft delete, filtering, pagination, and statistics — and interacts exclusively with `PrismaService`. DTOs live in `dto/` (`CreateFeedbackDto`, `UpdateFeedbackDto`, `FeedbackFilterDto`) and are validated with `class-validator` decorators. The controller is a thin HTTP layer that delegates every operation to the service, never holding business logic. Dependency direction is one-way: controller → service → PrismaService; the module exports only `FeedbackService` for reuse by other modules.
