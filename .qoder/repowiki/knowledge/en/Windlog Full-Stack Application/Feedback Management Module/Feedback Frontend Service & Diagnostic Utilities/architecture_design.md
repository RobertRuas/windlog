Three cohesive files form a small frontend utility layer:
- `src/services/feedback.service.ts` is the HTTP client: it imports a shared `api` instance (axios-based) and exposes pure async functions (`createFeedback`, `getFeedbacks`, `getFeedbackById`, `updateFeedback`, `deleteFeedback`, `getFeedbackStats`) against `/api/v1/feedbacks`. All request/response shapes are typed via local TypeScript interfaces (`Feedback`, `CreateFeedbackPayload`, `UpdateFeedbackPayload`, `FeedbackFilters`, `PaginatedResponse<T>`, `ApiResponse<T>`), keeping components free of API concerns.
- `src/utils/consoleCapture.ts` is a stateful in-memory logger: `startConsoleCapture()` monkey-patches `console.error/warn/log/info` and registers `window.onerror` / `unhandledrejection` listeners; `stopConsoleCapture()` restores originals. A bounded array (`MAX_LOGS = 50`) holds `CapturedLog` entries with sanitised args.
- `src/utils/technicalContext.ts` is a pure collector: `collectTechnicalContext()` reads `navigator`, `window.screen`, `performance.timing`, and feature-detection APIs to build a `TechnicalContext` object mirroring the shape attached to each `Feedback` record.

Dependency direction is one-way: both utils are imported by the feedback service (which re-exports their types like `ConsoleLog` and `TechnicalContext` so callers get a unified contract). There is no cross-import between the two utils — they are independent helpers consumed by the service or UI layers.
