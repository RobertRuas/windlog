The repository is split into two co-located halves: `API/` (NestJS server) and `src/` (React client). The NestJS root `app.module.ts` registers every feature module (`Auth`, `Users`, `Projects`, `Upload`, `Notifications`, `WeeklyTimesheet`, `Feedback`, `SystemLog`) under a single tree, all sharing Prisma via `database/prisma.service.ts`. Each backend module follows the strict `{name}.module.ts + {name}.controller.ts + {name}.service.ts + dto/{name}.dto.ts` layout. The frontend mirrors this structure one-to-one: `src/pages/<feature>/` pages call `src/services/<feature>.service.ts` files that wrap axios calls to the matching NestJS endpoints, and TanStack Query keys follow the `['entity', filter?]` / `['entity', id]` convention. Cross-cutting concerns are centralized in `API/src/common/` (guards, interceptors, filters, decorators) and `src/components/ui/` (shared UI primitives), while routing, auth guards (`ProtectedRoute`, `AdminRoute`, `AdminOrHRRoute`), and i18n live in `src/App.tsx` and `src/i18n/`. Prisma schema is the single source of truth for types on both sides.
