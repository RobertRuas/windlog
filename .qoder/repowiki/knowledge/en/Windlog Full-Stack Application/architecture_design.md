The repository is split into two co-dependent halves wired together by REST endpoints under the global prefix `/api/v1`:

- Backend (`API/src/app.module.ts`) bootstraps a NestJS application that registers every feature module (Auth, Users, Projects, Upload, Notifications, WeeklyTimesheet, Feedback, SystemLog) in a single root `AppModule`. Cross-cutting concerns are applied globally in `main.ts`: Helmet + CORS + compression, a global `ValidationPipe`, `HttpExceptionFilter`, `TransformInterceptor`, and `LoggingInterceptor` that persists HTTP requests to the SystemLog table.
- Frontend (`src/App.tsx`) wraps all routes with `QueryClientProvider` (TanStack Query), `BrowserRouter`, and role-based route guards (`ProtectedRoute`, `AdminRoute`, `AdminOrHRRoute`, `AuthOnlyRoute`). Each page lives under `src/pages/<feature>/` and calls the matching service in `src/services/<feature>.service.ts`, which uses a shared fetch-based `api.ts` client.
- The contract between halves is the NestJS controller/service layer: each backend module exposes CRUD endpoints that correspond one-to-one with a frontend service file, and Prisma schema in `API/prisma/schema.prisma` is the authoritative type source consumed by both sides.
- Shared cross-cutting code on the backend lives in `API/src/common/` (decorators, DTOs, filters, guards, interceptors); on the frontend it lives in `src/components/ui/` (reusable UI primitives) and `src/components/layout/` (structural components like AppLayout/Sidebar).
