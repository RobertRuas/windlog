Standard NestJS module layout: `weekly-timesheet.module.ts` registers the controller and service and exports the service; `weekly-timesheet.controller.ts` exposes REST endpoints under `/api/v1/weekly-timesheets` protected by `@UseGuards(AuthGuard('jwt'))`; `weekly-timesheet.service.ts` holds all business logic (RBAC checks via `canManageTimesheet` / `canViewTimesheet`, ISO-week date math via `getMondayOfISOWeek`, soft delete, nested update of days and entries). DTOs live in `dto/`: `CreateTimesheetDto`, `UpdateTimesheetDto` (with nested `UpdateDayDto` → `UpdateEntryDto`), and `TimesheetFilterDto` extending a shared `PaginationDto`. The service is the sole data-access layer, using `PrismaService` directly — no repository abstraction. Dependency direction is one-way: controller → service → PrismaService; the module imports `PrismaService` from `../../database/prisma.service.js` and re-exports the service for consumers.
