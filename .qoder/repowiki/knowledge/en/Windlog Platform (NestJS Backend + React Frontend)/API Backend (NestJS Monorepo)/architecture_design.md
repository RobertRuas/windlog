The application is rooted in `src/app.module.ts`, which imports every feature module (`AuthModule`, `UsersModule`, `ProjectsModule`, `NotificationsModule`, `UploadModule`, `SystemLogModule`, `WeeklyTimesheetModule`) alongside the global `ConfigModule`. `src/main.ts` is the single entry point that registers cross-cutting concerns globally: `ValidationPipe` (whitelist + forbidNonWhitelisted), `HttpExceptionFilter`, `TransformInterceptor`, and `LoggingInterceptor` (which persists requests via `SystemLogService`). Each business module adheres to the `{name}.module.ts + {name}.controller.ts + {name}.service.ts + dto/{name}.dto.ts` layout; controllers are thin HTTP handlers delegating all logic to services, which own all Prisma queries. The `common/` directory provides shared decorators (`@CurrentUser`, `@Roles`), guards (`RolesGuard`), interceptors, DTOs, and the singleton `PrismaService`. All modules share the same configuration source (`config/env.validation.ts`) and communicate only through NestJS dependency injection — there is no direct cross-module coupling beyond module imports.
