Two-layer application sharing API/prisma/schema.prisma as the single source of truth for types and database structure. The backend (API/) is a NestJS monorepo bootstrapped via AppModule that registers global interceptors, filters, guards, and Swagger docs, then exposes feature modules (Auth, Users, Projects, Notifications, Upload, System-Log, Weekly Timesheet) each following the strict {name}.module.ts + {name}.controller.ts + {name}.service.ts + dto/{name}.dto.ts pattern. The frontend (src/) mirrors this structure: pages under src/pages/ call typed services in src/services/ which wrap axios calls to the same endpoints, with TanStack Query managing cache keys using the ['entity', filter?] convention. Auth flows through JWT strategies on the backend and token storage on the frontend, while Prisma-generated types flow into both layers via shared DTOs and TypeScript interfaces. LoggingInterceptor maps HTTP requests to LogAction entries stored via the System-Log module, and all business entities use soft delete with deletedAt filtering.
