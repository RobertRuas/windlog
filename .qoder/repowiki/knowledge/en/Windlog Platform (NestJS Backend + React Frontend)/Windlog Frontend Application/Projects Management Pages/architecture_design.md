Two top-level pages compose the feature: `ProjectsPage.tsx` (list + CRUD via inline mutations) and `detail/ProjectDetailPage.tsx` (tabbed detail view). Each page is an orchestrator that owns state and TanStack Query calls, delegating UI to colocated components under `components/` (for the list page) and `detail/components/` (for the detail page). Write operations on the detail page are centralized in `detail/hooks/useProjectMutations.ts`, which returns grouped mutation hooks (project, turbine, member, file) that invalidate the `['project', id]` query key after success. All data fetching goes through `@/services/project.service` and `@/services/user.service`; types (`ProjectListItem`, payloads) are imported from those services rather than redefined locally. The list page uses a shared `DataTable` component from `@/components/ui/DataTable` for consistent table rendering, while modals (`ProjectModal`, `ProjectEditModal`, `TurbineModal`) are self-contained form dialogs. Navigation between pages uses react-router-dom's `useNavigate` with routes `/projects` and `/projects/:id`.
