The module is organized into five horizontal layers with a strict dependency direction: `components/` (presentational) → `hooks/` (stateful logic via TanStack Query) → `services/` (HTTP calls through a single `api.ts` fetch wrapper) → `utils/` (pure functions like JWT decoding) → `types/` and `constants/` (shared interfaces and lookup tables). `src/services/api.ts` is the single HTTP entry point that centralizes JWT injection, 401 auto-logout, and error handling; every domain service (`auth.service.ts`, `upload.service.ts`, etc.) wraps `api.get/post/put/delete` and unwraps the NestJS `{ data, message, statusCode, timestamp }` envelope. Layout components (`AppLayout`, `Sidebar`) compose UI primitives from `components/ui/` and pull user state via TanStack Query keys following the `['entity', filter?]` convention. The `useFileUrl` hook encapsulates temporary file URL fetching with a 4-minute staleTime matching the backend token TTL. All business types live in `types/user.types.ts` and are mirrored by service-layer interfaces, keeping the contract between frontend and NestJS backend explicit.
