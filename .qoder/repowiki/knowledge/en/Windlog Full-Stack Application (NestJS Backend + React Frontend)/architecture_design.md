The repository is a monorepo containing two distinct applications sharing domain concepts:

**Backend (API/)**: NestJS application following strict module boundaries. Each business domain lives under `src/modules/<name>/` with the exact structure `{name}.module.ts`, `{name}.controller.ts`, `{name}.service.ts`, and `dto/{name}.dto.ts`. The root `AppModule` imports all feature modules (Auth, Users, Projects, Upload, Notifications, SystemLog, WeeklyTimesheet). Global cross-cutting concerns are centralized in `src/common/`: DTO validation via class-validator decorators, HTTP exception filter, response transform interceptor, logging interceptor, and role guards. Database access goes exclusively through `PrismaService` injected into services — controllers never touch the database directly. All routes use `/api/v1` prefix with Swagger/OpenAPI documentation at `/api/docs`.

**Frontend (src/)**: React application using Vite, React Router v6 for routing, TanStack Query for data fetching/caching, and Sonner for toast notifications. Pages follow `{PageName}.tsx` with colocated `components/` and `hooks/` directories. API calls go through `src/services/*.service.ts` files that wrap the central `api.ts` client (fetch-based, not axios), which handles JWT injection, 401 auto-logout, and error formatting. UI components live in `src/components/ui/` (generic) and `src/components/layout/` (structural like Sidebar/AppLayout).

**Shared conventions**: Prisma schema (`API/prisma/schema.prisma`) is the single source of truth for types; soft delete via `deletedAt` on all business entities; RBAC with ADMIN/HR/STANDARD roles enforced via guards and route wrappers (`ProtectedRoute`, `AdminRoute`, `AdminOrHRRoute`).
